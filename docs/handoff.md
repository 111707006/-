## 怎麼執行

這台電腦原本沒有 Node.js，已用 winget 裝了 LTS（`C:\Program Files\nodejs`）。新開的終端機才會有 PATH。

```bash
cd site
npm install
npm run build        # 寫出 site/index.html
npm run build:dev    # 寫出 site/dev.html，多了 F（飛行）與 B（基準測試）
```

要用網頁伺服器開，不能直接點檔案（影片要從 `../media-library/` 載入）：在倉庫根目錄執行 `python -m http.server 8732`，開 `http://127.0.0.1:8732/site/index.html`。

**Chrome 預設會用 AMD 內顯（約 13 fps）。** 要用 GTX 1650，啟動 Chrome 時加 `--force_high_performance_gpu`，或在 Windows 的圖形設定把 Chrome 指定為高效能。

驗證方式：Claude in Chrome 擴充功能沒連上，所以是另開一個獨立設定檔的 Chrome（`--remote-debugging-port=9333 --force_high_performance_gpu`），用一支只靠 Python 標準函式庫的小程式透過除錯埠讀數字、截圖、送滑鼠鍵盤事件。那支程式在暫存資料夾，不在倉庫裡，需要時重寫即可。

## 驗證過與沒驗證過的

在 GTX 1650、Chrome 157、桌機橫向視窗裡實際看過：

- 出生點正前方看得到電腦，螢幕播放靜音預覽。
- 游標指到電腦：出現「影片電腦　點擊播放」、螢幕邊緣亮金色、游標變手形。
- 點擊：鏡頭切到正面，開機畫面約 1.6 秒，接著播放有聲的形象影片；HTML 播放器與場景裡的螢幕對齊。
- 切到直式影片：完整顯示、左右留黑、沒有裁切。
- Esc 離開：影片暫停，鏡頭回到原位。
- 壓縮版 `index.html` 與開發版都跑過上面的流程，瀏覽器沒有報錯。
- 游標鎖定下用準星點選：準星移到電腦上變成金色的圈，點擊進入正面模式，Esc 離開後游標重新鎖定。（後來補測到的。）

寫了但**沒有驗證**：

- **手機與觸控**：短按點選、直拿時整頁旋轉的座標換算，都沒有裝置可測。
- 關閉鈕、點螢幕外離開：程式與 Esc 走同一個函式，但沒有個別點過。
- 頻道清單停住 2.5 秒淡出：只看到它淡出後的畫面，沒有逐項確認回來的時機。
- Medium 與 Low 畫質、內顯上的樣子。
- 距離超過 70 公尺時暫停預覽。
- 環境音在播放影片時淡出：自動化環境聽不到聲音。

## 效能

60 秒腳本飛行（開發版的 B 鍵），視窗固定在 860×578 全解析度、繪製距離 1，GTX 1650，上游與網站版交替跑。GPU 每格時間（毫秒）：

| | 平均 | 第 99 百分位 | 最大 |
|---|---|---|---|
| 上游，四次 | 10.87–10.88 | 13.89–14.02 | 14.22–14.42 |
| 網站版（加了電腦、螢幕影片、光暈），四次 | 8.72、8.79、10.85、11.16 | 10.94–14.35 | 11.40–14.61 |

加了電腦之後量不出變慢：網站版最慢的一次比上游多 0.3 毫秒，有兩次反而快 2 毫秒。網站版兩次之間的差距比它與上游的差距還大，原因沒有查出來，所以這組數字只能說「沒有明顯下降」，不能當成精確的成本。

這台電腦量不到 `prompt.md` 的目標規格（那是 RTX 5070 Ti 在 2560×1440，平均 ≤ 11 ms、最差 ≤ 16.7 ms），只能比較加了電腦之前與之後。整格時間的最大值是 20.9–28.5 ms，超過 16.7 ms。
