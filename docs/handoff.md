## 程式放在哪

沒有建置步驟，直接是 ES 模組。

| 檔案 | 內容 |
|---|---|
| `site/shader.js` | WGSL 全螢幕光線追蹤：方塊求交、磚牆、石材、稜紋發光玻璃、影片螢幕、工作站介面、接待螢幕、地面反射、線光源與光暈、色調映射 |
| `site/main.js` | 場景資料（`boxes`、`lines`）、鏡頭路徑（`KEYS`）、影片圖集、捲動、HTML 標示的透視矩陣、依幀時間調整解析度、不支援 WebGPU 時的替代 |
| `site/index.html` | 版面、五站的說明、牆面與櫃檯上的 HTML 標示（`.wl`） |
| `site/assets/` | `fg.png`（logo）、`fallback.jpg`（替代版背景，就是 AI 門面圖） |
| `index.html`、`.nojekyll` | 根目錄轉址到 `site/`，給 GitHub Pages |
| `docs/sample-shots/` | 目前版本的截圖 |

要點：

- 場景是一份方塊清單加一份線光源清單，由 uniform 傳進著色器。上限 `MAX_BOXES` 72、`MAX_LINES` 24（在 `shader.js`），目前用了約 58 與 18。
- 材質編號：0 磚、1 石材、2 發光玻璃、3 影片螢幕、4 大廳後牆、5 工作站螢幕、6 黑金屬、7 接待螢幕、9 地面。螢幕類的方塊把自己的索引放在 `par`，著色器用它讀尺寸。
- 座標：中庭沿 z 軸，入口在 z=0，鏡頭從 z=41 往 -z 看。左牆內面 x=-10，右牆 x=10。玻璃量體的範圍寫死在著色器的 `GMIN`／`GMAX`，改 `main.js` 的方塊時要一起改。
- 鏡頭：`KEYS` 的 `t` 是站點編號（0 到 4，中間的小數是繞過櫃檯的經過點）。捲動每 1.25 個螢幕高走一站。
- 兩面螢幕的畫面來自一張 2D 畫布圖集，每格把影片畫上去再上傳。左牆六格用 `media-library/previews/`，右牆是 `welcome-to-fg-gvs`（這次新做的預覽與封面）。
- 牆上與櫃檯上的字是 HTML，用與著色器同一台鏡頭算 `matrix3d`。`data-o` 原點（公尺）、`data-r` 文字方向、`data-s` 每像素幾公尺、`data-stops` 只在哪幾站顯示。沒有遮擋判斷。
- 光沒有陰影，全部是解析式近似。玻璃量體的光在大廳內用條件式關掉，避免穿透天花。

除錯用的網址參數：`?t=2` 固定在第 2 站、`?time=12` 固定時間、`?scale=1` 固定解析度、`?once=1` 只畫一格、`?still=1` 不載影片只用封面、`?offscreen=1` 畫到離屏材質再讀回 2D 畫布。

## 怎麼驗證

這個雲端環境**沒有顯示卡**。無頭 Chromium 可以用軟體模擬 WebGPU（`--enable-unsafe-webgpu --enable-unsafe-swiftshader --ignore-gpu-blocklist`），但 **WebGPU 畫布一呈現，裝置就會被銷毀**。所以截圖一定要加 `?offscreen=1&once=1`，等 `window.__done` 再截。1280×720 一格約 3 秒。

倉庫根目錄起伺服器後，截圖網址長這樣：

`http://localhost:8770/site/index.html?t=3&time=12&scale=1&once=1&still=1&offscreen=1`

海洋版的交接提到負責人的電腦有 GTX 1650 和可用 WebGPU 的瀏覽器；真正的畫布路徑要在那裡看。
