## 怎麼執行與驗證

沒有建置步驟，`site/` 直接是 ES 模組。要用網頁伺服器開（影片從 `../media-library/` 載入）。

`.claude/launch.json` 有一個叫 `site` 的伺服器（倉庫根目錄，埠 8741），用內建瀏覽器的 `preview_start` 啟動，開 `http://localhost:8741/site/index.html`。Python 在 `C:\Users\a0900\AppData\Local\Programs\Python\Python312\python.exe`，不在 PATH。ffmpeg 在 PATH。

### 兩種驗證方式

- **獨立的無視窗 Chrome（GTX 1650）**：`docs/tools/` 的小程式，只靠 Python 標準函式庫走 CDP。伺服器要先開著，一定要帶 `headless`（不帶會跳出視窗搶焦點）。
  - `python docs/tools/cd_shots.py <輸出資料夾> http://localhost:8741/site/index.html headless [0,1,p3,…]`：用 `?t=` 固定站點拍截圖。`d` 是 1280×720，`p` 是 390×844。不給清單就拍全部。約一分鐘。
  - `python docs/tools/cd_run.py <輸出資料夾> <網址> headless`：開場的五格、真的捲動下每站的幀率與畫布大小、一進來就捲動、手機尺寸。約三分鐘。
  - `python docs/tools/cd_fb.py <輸出資料夾> <網址> headless`：用 `?nogpu` 看靜態版本，手機與桌機尺寸各走五站。
  - `cdp_base.py` 是從海洋版搬來的，前半段（啟動 Chrome、WebSocket、`call`／`ev`／`shot`）被另外三支 `exec` 進去用；後半段是海洋版的流程，這裡用不到。
- **內建瀏覽器（AMD 內顯）**：WebGPU 可用，是唯一量得到內顯的地方。**面板被隱藏時 `requestAnimationFrame` 不會跑**，頁面停在載入畫面，量不到任何東西；要請負責人把瀏覽器面板打開。無視窗 Chrome 加 `--force_low_power_gpu` 也還是跑在獨顯上，試過了。

截圖輸出放 `docs/local-check/`（已列入 `.gitignore`）。`docs/sample-shots/` 是第三輪結束時的畫面（`intro.jpg` 是開場四格，`static-phone.jpg` 是靜態版本）。

### 除錯用的網址參數

`?t=2` 固定在第 2 站（也略過開場）、`?time=12` 固定時間、`?scale=1` 固定解析度、`?once=1` 只畫一格、`?still=1` 不載影片、`?nointro` 略過開場、`?nogpu` 強制靜態版本、`?offscreen=1` 畫到離屏材質再讀回（給沒有顯示卡的雲端環境截圖用；在這台電腦不需要）。

## 程式放在哪

| 檔案 | 內容 |
|---|---|
| `site/shader.js` | WGSL 全螢幕光線追蹤：方塊求交、椅子的距離場、磚、石材、發光玻璃、影片螢幕、工作站介面、格柵天花、地面反射、線光源與光暈、色調映射 |
| `site/main.js` | 場景資料（`boxes`、`lines`）、鏡頭路徑（`KEYS`）、影片圖集、捲動、開場、直式螢幕的鏡頭修正、HTML 標示的透視矩陣、解析度調整、靜態版本 |
| `site/index.html` | 版面、載入畫面、五站的說明、牆面與櫃檯上的 HTML 標示（`.wl`） |

要點：

- **材質編號**：0 磚、1 石材、2 發光玻璃、3 影片螢幕、4 大廳後牆、5 工作站螢幕、6 黑金屬、7 接待螢幕、8 大廳天花、9 地面、11 椅子。
- **方塊分兩段**：`nOuter` 之前是大件；之後是作業中心的長桌與螢幕，著色器先測視線有沒有穿過那一區（`OP0`／`OP1`），沒有就整段跳過。新增作業中心以外的方塊要放在 `const nOuter = boxes.length` 之前。
- **椅子不是方塊**：`shader.js` 的 `chairs()` 是距離場，六張椅子靠 x 方向的重複畫出來，只在 `CH0`／`CH1` 的範圍內步進。椅子的位置寫死在著色器裡（x = -4.5 + 1.8k，z ≈ -7.78），改長桌位置時要一起改。
- **uniform 開頭 28 個浮點數**（7 個 vec4）：鏡頭位置與時間、前向與 tan、右向與長寬比、上向與暖光亮度、解析度與方塊數與線光源數、站點與圖集參數、`ex`（`nOuter`、玻璃亮度）。`MAX_BOXES` 112、`MAX_LINES` 24。
- **座標**：中庭沿 z 軸，入口在 z=0，首頁鏡頭在 z=41 往 -z 看。左牆內面 x=-10，右牆 x=10。玻璃量體的範圍寫死在著色器的 `GMIN`／`GMAX`。
- **開場**：`tI` 是開場的秒數；暖光 0.3 秒起亮、玻璃 1.6 秒起亮、鏡頭 6 秒就定位（`introK`）；`introK > 0.82` 才顯示首頁標題。捲動時 `tI` 以五倍速走。
- **直式螢幕**：`tall` 是直式的程度。首頁少拍天空；第 1 站往左退、往右看；第 3 站退到門口並把水平視角放寬到 33°；第 4 站退後右移並收窄到 21°。都在 `frame()` 開頭那一段。
- **解析度調整**：倍率上限 1.5（一倍螢幕上等於超取樣），下限 0.45。`best` 是看過最短的每格時間；每格超過約 21.7 毫秒就降，貼著 `best` 就試著升，升了又掉回來的話下次等更久。降到下限還不到 20 幀、連續三次，就換靜態版本。
- **牆上的字**是 HTML，用與著色器同一台鏡頭算 `matrix3d`，沒有遮擋判斷。`data-stops` 限定只在哪幾站顯示：兩面牆的大字只在自己那一站，櫃檯的字在第 0、4 站。
- **重複的標題**：第 2、4 站的說明面板不顯示 `h2`（牆上已經有同名大字）；靜態版本沒有牆上的字，照常顯示。
- **工作站螢幕**的預覽窗取樣作品牆那六格圖集，所以播的是真的作品。
- 片段著色器裡依材質分支的地方只能用 `textureSampleLevel`，不能用 `textureSample`。
- 光沒有陰影，全部是解析式近似。
- 三個檔都是 CRLF 行尾。**不要用 `sed -i` 改它們**（會變成 LF，整個檔都算有改動）；用 Edit 工具，或用 Python 以 `newline=''` 讀寫。

## 審查的結論

三輪下來，首頁約 7.5 分，室內兩站約 5.5 分。每一輪都重複出現的是同一件事：**參考圖的燈是細而亮的線、周圍黑得乾淨；我們的是寬而霧的光暈，暗部泛灰**。這要重調整套光照與色調映射（`lighting()`、`ground()` 的暈光、`halo()`、最後的 `col *= 1.25` 與映射曲線），不是修個別物件。

第三輪審查列的、還沒處理的：

1. 牆上的「BRAND FILM／BRAND CONTENT」跟著牆面透視歪斜，作品牆那站的字壓到螢幕上緣。
2. 作業中心後牆太空，上方三分之二是一片灰。
3. 櫃檯正面沒有材質，底部燈帶糊成霧。
4. 首頁地面的燈條是寬光暈，有一條穿過副標與按鈕。
5. 形象影片那站，遠處大廳的小螢幕疊在說明編號後面。
6. 椅子仍像剪影；工作站螢幕邊框偏厚、介面底色偏藍灰。
7. 手機的作業中心與櫃檯，上半部天花板條紋佔太多。
8. 形象影片那站左側的發光玻璃過亮；櫃檯那站右緣有一條過亮的白線。
9. 開場第一格幾乎全黑，像沒載完；3 秒之後鏡頭幾乎不動，尾段偏拖。建議一開始留一條亮線，總長縮到約 4 秒。

- **審查會前後不一**。牆上的大字第二輪被列為「不該動」，第三輪變成第一項缺陷。分數只當參考，最後由負責人看了算。

## 效能：負責人問了「很吃效能嗎」

我的回答是：偏吃，而且對手機和內顯不利。全螢幕光線追蹤的運算量跟像素數成正比，地面的像素還要多算一次反射。我提的四個做法（他還沒回要不要做）：

1. 手機與內顯關掉地面反射，或改成便宜的假反射。大約省近一半。
2. 弱裝置上椅子換成簡單的形狀，或不畫。
3. 手機上只播當下那一站的影片，不要七支同時解碼。
4. 做成高、低兩級畫質，依裝置自動選。

我建議先做第 1 與第 4 項，再重調光照。
