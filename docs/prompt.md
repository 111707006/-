# 建置提示詞

仿照 `abyssal-garden/prompt.txt` 的寫法：優先順序、限制、目標規格、場景、操作、驗證、完成條件。這份是給在有顯示卡的電腦上實作的工作階段直接執行的。細節與理由見 `docs/spec.md`；兩者衝突時以本文件為準並回報。

---

把 `abyssal-garden/` 的水下世界改造成 FG STUDIO 的官方網站。訪客潛入一個可以自由探索的水下世界，世界裡有會發光的復古電腦與寶箱；點電腦看影片，點寶箱看資訊。全站圍繞一句標語：「先理解你的品牌，再說好你的故事。」

優先順序（互相衝突時依此順序）

1. 找得到資訊：不游動、原地轉一圈，就能看到並點到每一個可互動物件
2. 畫面品質：不低於上游
3. 在目標規格上幀率穩定
4. 檔案大小

限制

- 從 `abyssal-garden/source/` 複製成 `site/` 再改。不修改 `abyssal-garden/`。
- 沿用上游的做法：直接用 WebGPU，不引入 Three.js、Babylon.js 或任何引擎與前端框架。
- 場景物件全部由程式生成，不使用模型檔與貼圖檔。唯一的外部素材是 `media-library/` 的影片與封面。
- 繪製迴圈不配置記憶體。緩衝區全部預先配置。
- 新網格一律加在 `meshes` 陣列尾端並新增獨立的繪製呼叫；上游以數字索引存取這個陣列，不可插入中間。
- 保留上游的三段畫質、載入失敗自動降級、依幀時間調整解析度與繪製距離。
- 所有文字放在 HTML，不畫進場景。繁中與英文並存，切換語言不重新載入場景。
- 全站一個強調色：金色，只用在可以點的東西上。
- 不出現客戶名稱與客戶 logo。不填入尚未提供的價格；VIP 與到場攝影顯示「專屬報價」。
- 保留上游的 MIT 授權聲明，並註明場景改造自 Abyssal Garden。

目標規格

- 與上游相同：Windows 11 25H2、Chrome 157、RTX 5070 Ti、Ryzen 7800X3D、180 Hz 螢幕。
- 2560×1440 全解析度。GPU 幀時間平均 ≤ 11 ms，60 秒腳本飛行中沒有任何一格超過 16.7 ms。
- 新增的電腦、螢幕影片、寶箱與光加入後，仍須符合上面的標準。
- 手機沒有另訂目標：沿用上游的畫質分級與自動調整，負責人的 iPhone 直拿能游、能點、影片會播即可。

場景

- 上游的世界全部保留：海帶森林、光束、焦散、岩拱、沉船、鯨尾石雕、魟魚、魚群、紫色洞穴。
- 廣場：出生點所在的一塊空地。所有可互動物件都在這裡。
- 兩台復古電腦，一體式的八零年代造型，放大數倍，帶海底沉積的質感，受水下光照、霧與陰影影響：
  - 影片電腦，在出生點正前方。
  - 資訊電腦，在它旁邊。
- 螢幕自發光，亮度足以產生泛光並照亮周圍的水；遠看播放 6 秒靜音預覽；帶映像管質感：水平掃描線、紅綠藍細直條紋、四角變暗、輕微桶狀彎曲、亮度緩慢呼吸。
- 五個寶箱分佈在出生點四周：聯絡、方案、合作方式、實績、關於。箱縫透出金光，上方有向上飄散的金色光點，一道細光柱穿過霧氣。亮度緩慢脈動。
- 光分兩級：聯絡與方案最亮最大，其餘次之。
- 佈局規則：站在出生點不游動，原地轉一圈，兩台電腦與五個寶箱都看得到。不必同時出現在一個畫面裡，可以分佈在四周。每個都不被海帶、岩石、魚群擋住，大到看得出是什麼。桌機橫向與手機直向都要成立。
- 進站時面向的方向要有影片電腦與標語。
- 廣場以外是風景：不放必要資訊，不放正式的可互動物件。

操作

- 自由游動，保留上游的碰撞。桌機 WASD 移動、Q／E 升降、Shift 加速；游標不鎖定，能自由點擊（轉頭方式：按住拖曳，或鎖定加準星，兩種都試後擇一）。
- 手機直拿：取消上游的強制橫向。按住游動，短按且幾乎沒移動算點擊。
- 指到可互動物件：游標變手形、光暈增強、顯示名稱。
- 從出生點就能直接點每一個物件，不設距離限制；點擊後鏡頭平滑滑行過去，不穿過岩石。
- 點電腦：鏡頭滑到正前方，螢幕接近佔滿畫面，外框仍看得到；螢幕先跑一小段復古開機畫面；HTML 播放器對齊場景裡螢幕的四個角；疊上映像管覆蓋層。影片電腦播放完整影片，有聲音，可用頻道清單切換形象影片與六種溝通情境的範例；直式影片完整顯示、左右留黑、不裁切。資訊電腦以復古視窗一句一窗說明 GVS。Esc、關閉鈕或點螢幕外離開，鏡頭退回原位。
- 點寶箱：箱蓋打開、光迸出，內容以復古視窗彈出。開過的寶箱保持打開、光變柔和，重新整理後仍記得。
- 潛水日誌：角落常駐的清單，列出兩台電腦與五個寶箱，顯示已開啟的數量。每一項都能點，點了鏡頭滑過去並開啟。全部開完出現結尾畫面。
- 常駐聯絡按鈕：任何狀態下都看得到。
- 環境音保留，預設靜音，有開關；播放完整影片時淡出。

頁面

- 載入畫面就是第一屏資訊：FG 拆開成 For God 的開場動畫（約 1.3 秒，每次都播）、標語、一句話說明、「申請品牌試做」按鈕、載入進度。載入完成後一顆「潛入」按鈕，只有這一個入口。
- 內容視窗：復古電腦視窗樣式；可用 Esc、關閉鈕、點視窗外關閉；焦點管理正確；手機上撐滿寬度。
- 內容：依 `docs/spec.md` 第 9 節與 `docs/website-brief.md`。文案來源是 `original-site/text-zh.txt` 與 `text-en.txt`。
- 替代版本：瀏覽器不支援 WebGPU、取不到裝置、最低畫質仍失敗、或使用者設定減少動態時自動顯示。同一份 HTML 改成一般捲動頁面，以完成場景的截圖為背景。內容與主版本完全相同，不是錯誤頁。

驗證

- 視覺評審：一個只看得到渲染結果、看不到程式與推理過程的獨立子代理。給它：在出生點原地轉一圈的一組截圖（每 45 度一張，桌機橫向與手機直向各一組）、每個可互動物件的近景、兩台電腦的正面模式，全部在有顯示卡加速的瀏覽器裡以目標解析度擷取；另加一段從出生點游一圈的錄影，用來抓閃爍、鋸齒、物件突然出現與色帶。它回報排好優先順序的具體缺陷。反覆修正，直到它回報的問題都不高於「輕微」。
- 另外請評審專門回答三個問題：
  1. 只看出生點轉一圈的那組圖，能不能數出七個可以點的東西，並分辨哪兩個最重要？
  2. 復古電腦放在這個水下世界裡協不協調？
  3. 正面模式看起來像不像一台老電腦的螢幕？
- 效能：GPU 時間戳查詢，加上腳本飛行的幀時間紀錄。回報平均、第 99 百分位、最大值。在加入每一類新物件（電腦、螢幕影片、寶箱與光）前後各量一次，回報差異。
- 功能：`docs/spec.md` 第 11 節的驗收清單逐項通過。

分批

- 第一批：一台電腦，遠看發光播預覽，點擊後轉正面播放。到這裡停下來給負責人看。
- 第二批：一個寶箱，發光、點擊、開箱、彈出視窗。
- 第三批：廣場與全部物件、光的分級、潛水日誌、常駐聯絡按鈕、載入畫面。
- 第四批：全部內容、雙語、表單（送出後訊息裝進瓶子浮向水面）、YouTube 作品清單、替代版本。
- 第五批：聲納（送出一圈聲波，沒開過的物件回一道光與回音）、領航魟魚（訪客停著不動時游過來，帶往下一個沒開過的物件）、打磨。
- 上線後：沉船放映室。

每一批都要能單獨上線。

完成條件：兩道驗證關卡與驗收清單全部通過。交付 `site/` 的原始碼與建置成品、成品大小、效能報告、評審的最終意見，以及每個固定視點的截圖。
