# FG STUDIO 官方網站：實作規格

寫給在**有顯示卡的電腦**上接手實作的工作階段。先讀完本文件，再動手。

相關文件：

- `CONTEXT.md`：詞彙表。本文件的用詞以它為準。
- `docs/website-brief.md`：品牌、客群、方案、流程的討論結果。本文件不重複其內容，只引用。
- `docs/reference-teardown.md`：參考網站拆解與 Abyssal Garden 原始碼研究。
- `abyssal-garden/`：上游專案的原樣副本，**不要修改**。

## 1. 現況與前提

- 尚未寫任何網站程式碼。
- 寫這份規格的環境沒有顯示卡，**從未實際執行過 Abyssal Garden**。本文件引用的程式位置來自閱讀原始碼，行為描述來自原始碼註解與 README。動工第一步是在目標電腦上跑起來並核對（見第 12 節階段 0）。
- 負責人實測原版在自己的 iPhone 上可以執行。機型與幀率未記錄。
- 本文件引用的行號對應上游提交 `a596354`。

## 2. 要做什麼

一個官方網站，主畫面是可以**自由探索**的寫實水下世界，由 Abyssal Garden 改造而來。訪客自己游，世界裡散落著會發光的東西：一到兩台**復古電腦**，以及多個**寶箱**。發光就是「這裡可以點」的提示。

- 點擊復古電腦：鏡頭滑到電腦正前方，螢幕佔滿畫面並開始播放。這個正面畫面的樣子參考 The InnerWebs 首屏的老電腦。
- 點擊寶箱：箱蓋打開，內容以復古視窗彈出。舊站的全部資訊分裝在各個寶箱裡。

全站圍繞一句標語：「先理解你的品牌，再說好你的故事。」

不採用「依序經過」作為唯一的瀏覽方式。依序的導覽路線可以有，但只是選項之一。

### 成功標準

1. 訪客進站後不用讀說明就知道可以游、可以點發光的東西。
2. 不想探索的訪客，從潛水日誌一次點擊就能到達任何內容；「申請品牌試做」在載入畫面與方案寶箱裡都有。
3. 不支援 WebGPU 或效能不足的裝置，能看到內容完整的替代版本，不出現錯誤訊息。
4. 影片內容不被裁切，直式與橫式都完整顯示。
5. 桌機 60 fps、負責人的 iPhone 30 fps 以上（實際門檻在階段 0 量測後校正）。

### 不做

- 後台。內容以資料檔維護。
- 客戶 logo 列、以客戶為單位的作品展示（見 `website-brief.md`）。
- 把依序瀏覽當成唯一方式。
- 自行編造尚未提供的數字，包括 VIP 月費與到場攝影價格。

## 4. 架構

兩層疊在一起：

1. **場景層**：全螢幕固定的 `<canvas>`，WebGPU 繪製水下世界。由上游程式改造。
2. **內容層**：一般 HTML，疊在場景上。包含導覽列與選單、物件名稱提示、內容視窗、電腦正面模式的播放器、表單。

兩層之間只透過三件事溝通：

- 內容層可以要求場景把鏡頭移到某個地點（選單的快速前往、導覽路線）。
- 場景回報游標或準星指到哪個可互動物件，內容層顯示它的名稱。
- 場景回報點到哪個物件，內容層打開對應的視窗或進入電腦的正面模式。

**所有文字內容都放在內容層**，不畫進場景。這樣文字可被搜尋引擎讀取、可被螢幕閱讀器朗讀、可切換語言，替代版本也能直接重用。

不引入任何前端框架或 3D 函式庫。沿用上游的建置方式（Node.js 加 esbuild）。成品不必維持單一檔案：影片與圖片是外部檔案。

## 5. 世界裡有什麼

**地點**是世界裡放了內容的一個位置。地點之間沒有固定順序。

### 5.1 進站

1. **載入畫面就是第一屏資訊。** 上游載入需要數秒建造世界。這段時間畫面上顯示：FG logo 拆開成 For God 的開場動畫（約 1.3 秒，每次進站都播）、標語、一句話說明 FG STUDIO 做什麼、「申請品牌試做」按鈕、載入進度。訪客還沒進水就知道這是誰、做什麼、下一步是什麼。
2. 載入完成後出現「潛入」按鈕。**不提供「直接看資訊」的入口選擇**：負責人決定不做進站兩扇門。替代版本只在裝置無法執行場景時自動出現（見第 8 節）。
3. 出生點在**廣場**（見 5.3）。正前方是影片電腦，螢幕亮著，標語浮在畫面上。不移動也看得到全部寶箱的光。
4. 一行操作提示，幾秒後淡出：桌機「WASD 游動、點發光的東西」；手機「按住游動、點發光的東西」。

### 5.2 復古電腦

共兩台。

| 電腦 | 位置 | 內容 |
|---|---|---|
| 影片電腦 | 出生點正前方 | 形象影片，以及六種溝通情境的範例影片，以頻道清單切換 |
| 資訊電腦 | 另一處，需游過去 | GVS 是什麼：三步驟與六種溝通情境的說明，以復古視窗一句一窗呈現 |

資訊電腦是否需要，或把這些內容改放寶箱，待負責人決定（見第 13 節）。

### 5.3 寶箱與廣場

五個寶箱，每個一個主題。舊站的資訊全部分裝在裡面。

| 寶箱 | 內容 | 舊站來源 | 光的等級 |
|---|---|---|---|
| 聯絡 | 聯絡表單 | 08 Start a project | 最亮 |
| 方案 | 單支製作／VIP／VIP DOUBLE 三欄；品牌試做的說明與申請按鈕 | 02 Pricing & Trial、03 VIP | 最亮 |
| 合作方式 | 從詢問到交付的步驟；三項保障（正式合約、NDA 可選、作品是否公開由客戶決定） | 03 VIP 卡片，流程為新增 | 次亮 |
| 實績 | MTV／KKBOX／Netflix 與 YouTube 作品 | 04 Work、06 Credits | 次亮 |
| 關於 | FG 代表 For God | 07 About | 次亮 |

文章有三篇以上時加第六個寶箱。

**廣場**：出生點是一塊空地。影片電腦在正前方，寶箱圍成半圈，全部在視線內，從出生點游十秒內都到得了。資訊不散落在整個世界。

廣場以外的海帶森林、沉船、鯨尾石雕、紫色洞穴是風景，留給想逛的人，可以放彩蛋，但**不放任何必要資訊**。

### 5.4 找得到東西

逛和找要分開：世界負責讓人記住 FG STUDIO，資訊要能很快拿到。以下都是必做。

- **發光分等級**：所有可互動物件都發金色光，穿透霧氣，遠處看得見光暈。聯絡與方案最亮最大，其餘次之，訪客第一眼被引到最重要的兩個。金色是全站唯一的強調色，只用在可以點的東西上。
- **潛水日誌**：角落常駐一份清單，列出影片電腦與每個寶箱，顯示「已開啟 3／6」。**清單的每一項都可以點，點了鏡頭就滑過去並開啟。** 它同時是進度、選單與捷徑。上游已有跳到固定視點的機制（數字鍵 1 到 6 呼叫 `lookAt(...POSES[n])`），以此擴充；移動用滑行，不要瞬間切換。全部開完出現一個結尾畫面。
- **已開啟的記號**：開過的寶箱保持打開、光變柔和；日誌裡打勾；重新整理後仍記得。
- **常駐聯絡按鈕**：畫面角落永遠有一顆，不論人在哪裡、在做什麼。LINE 官方帳號開通後接上。

### 5.5 導覽路線

依序瀏覽不做成選單按鈕，改由**領航魟魚**提供（見第 14 節）：訪客停著不動時，一隻發光的魟魚游過來，往下一個沒開過的地點游去，跟著牠就是導覽。訪客隨時可以不理牠。

## 6. 場景層的改動

以下每項都標明從上游哪裡著手。檔案路徑相對於 `site/`。

### 6.1 移動與操作

**上游現況**：`src/main.js` 的 `frame()` 每格依鍵盤、滑鼠、觸控更新自由攝影機，並用 `collide()` 讓鏡頭貼著岩石滑動而不穿過。桌機點擊畫布後鎖定游標，滑鼠移動等於轉頭。觸控：一指按住向前游並滑動轉向，兩指加速，README 標為實驗性。

**要做的**：保留自由游動與碰撞，但操作方式要改，因為訪客需要點東西。

- **桌機**：不鎖定游標。建議按住滑鼠拖曳來轉頭，放開後游標可自由點擊；WASD 與 Q／E 照舊。另一種做法是保留鎖定並在畫面中央放準星，點擊即點選準星指到的物件。兩種在階段 1 各試一次再定。
- **手機**：取消強制橫向（上游的 `rot` 與 `template.html` 相關樣式，以及進入時的全螢幕與鎖定橫向）。直拿時要能游、能點。觸控要區分「輕點物件」與「按住游動」：短按且幾乎沒移動算點擊。
- 直拿時水平視野變窄（垂直視角由常數 `TANH` 固定），需要依長寬比調整視角。
- 游速可比上游稍慢，世界範圍可縮小，讓內容之間的距離合理。上游的邊界是半徑 150 公尺。

### 6.2 鏡頭滑行

新增一個共用功能：把鏡頭從目前位置平滑移到指定的位置與注視點，期間暫停使用者操作。三處會用到：點擊電腦後的正面模式、選單的快速前往、導覽路線。上游的 `lookAt()` 是瞬間切換，`flyAt()` 是沿固定路徑；滑行要另外寫，並避免穿過岩石（可沿路取樣上游的碰撞距離函式，必要時先上升再前進）。

### 6.3 復古電腦

**上游現況**：場景物件在 `src/world.js` 用 `Mesh` 類別（`src/math.js`）以數學形狀建模，例如 `meshShip()`、`meshFluke()`、`meshManta()`。物件實例由 `makeWorld()` 裡的 `solid(mesh, x, y, z, 縮放, 四元數, 材質, 種子, …)` 擺放，每個實例 12 個浮點數。

**要做的**：

- 新增 `meshComputer()`：映像管顯示器、主機、鍵盤，一體式的八零年代電腦造型。尺寸放大到數倍，讓它在水下有存在感。
- 外殼使用上游的實體材質流程，受水下光照、霧與陰影影響，帶海底沉積的質感。
- **網格編號要注意**：`main.js` 的 `meshes` 陣列以位置編號，繪製程式到處用數字索引（`meshes[14 + i]`、`meshes[20 + i]`、`meshes[18 + i]`，以及 `for (let i = 0; i < 12; i++)` 的實體迴圈）。**新網格一律加在陣列尾端**，並為它們新增獨立的繪製呼叫。不要插入中間。
- 世界生成會在固定視點（`POSES`）與腳本路徑周圍保持暢通並佈景。電腦與寶箱的位置要納入這個機制，免得被海帶或岩石擋住。

### 6.4 電腦螢幕與正面模式

**遠看**：螢幕發光，播放影片的靜音預覽，是吸引人游過來的訊號。

- 新增一條繪製流程，在螢幕位置畫一個四邊形，取樣影片貼圖。上游完全沒有影片或外部貼圖。
- 影片來源是隱藏的 `<video>` 元素（靜音、循環、`playsinline`）。每格用 `device.queue.copyExternalImageToTexture()` 把畫面複製到一張一般貼圖。這比 `importExternalTexture()` 單純：後者的貼圖每格失效，綁定群組要每格重建。
- 四邊形畫進場景的 HDR 繪製階段並寫入深度，讓水的吸收、霧、光束、泛光都作用在它上面。螢幕是自發光，亮度要夠讓泛光產生光暈。
- 螢幕著色加上映像管質感，手法取自 The InnerWebs 的拆解：水平掃描線、紅綠藍細直條紋、四角變暗、輕微桶狀彎曲、亮度緩慢呼吸。
- 只有兩台電腦，所以同時解碼的影片最多兩支。距離太遠時暫停並顯示封面。

**點擊後：正面模式**

1. 鏡頭滑到電腦正前方，螢幕接近佔滿畫面，電腦外框仍看得到。
2. 內容層在螢幕的位置疊上一個 HTML 區域，大小與位置對齊場景裡的螢幕（用同一個投影矩陣算出螢幕四角的畫面座標）。實際的播放器、頻道清單、文字視窗都是 HTML，不畫進場景。
3. 疊一層映像管覆蓋（掃描線、弧形邊角、暗角），做法照 The InnerWebs：純 CSS 的固定覆蓋層。
4. 影片電腦：播放 `media-library/web/` 的完整版，有聲音。旁邊或下方是頻道清單，可切換形象影片與六種溝通情境的範例。直式影片在螢幕內完整顯示，左右留黑，不裁切。
5. 資訊電腦：以復古視窗一句一窗呈現 GVS 的三步驟與溝通情境。
6. 離開：Esc、關閉鈕、或點螢幕外。鏡頭退回原位，交還操作。

正面模式期間場景可降低更新頻率，環境音淡出。

### 6.5 寶箱

- 新增 `meshChest()`：箱體與箱蓋分開，才能做開箱動畫。
- 光：箱縫透出金色的光；上方有向上飄散的金色光點（用上游既有的加法混合粒子流程：`pGl`、`pSpr`、`pSnow`）；一道細光柱穿過霧氣，遠處可見。
- 亮度緩慢脈動。聯絡寶箱最亮。
- 點擊：箱蓋打開、光迸出，接著內容視窗彈出。開過的寶箱保持打開，光變柔和。

### 6.6 點選

**上游現況**：沒有任何物件點選。

**要做的**：可互動物件不超過二十個，用 JavaScript 做射線與包圍球的相交判定即可，不需要 GPU 點選。攝影機的基底向量在 `render()` 開頭算出並存入 `F[FX…UZ]`，視角常數是 `TANH`，可直接用來從螢幕座標產生射線。射線要檢查中間有沒有岩石擋住，免得隔牆點到。

- 指到可互動物件：游標變手形，物件光暈增強，內容層顯示物件名稱。
- 距離太遠時不能點，但顯示名稱與距離，鼓勵游過去；或點擊後自動滑行過去再開啟。兩種擇一，階段 3 試過再定。
- 每個可互動物件在選單裡都有對應的一般按鈕，確保鍵盤與螢幕閱讀器使用者能操作。

### 6.7 聲音

**上游現況**：`src/audio.js` 用 Web Audio 即時合成水下環境音，潛入時自動開始。

**要做的**：保留但預設靜音，導覽列有開關。完整影片播放時環境音淡出，播放結束淡入。

### 6.8 畫質與自動調整

保留上游的機制，不要重寫：`src/quality.js` 的三段畫質選擇、載入當掉時自動降一級、`frame()` 裡依幀時間調整解析度與繪製距離。

新增的電腦、螢幕、寶箱與它們的光在最低畫質下也要顯示，因為它們承載內容。

## 7. 內容層

### 7.1 視窗

內容視窗採復古電腦視窗的樣式：標題列、關閉鈕、內容區。這是從 The InnerWebs 借來的手法，也呼應場景裡的復古電腦。視窗打開時背景場景變暗變模糊（上游選單已有這個效果的 CSS）。

- 可用 Esc、關閉鈕、點擊視窗外關閉。
- 打開時焦點移入視窗，關閉時回到原來的按鈕。
- 手機上視窗佔滿寬度，內容區可捲動。

### 7.2 視覺紀律

取自 Cut/Run 的拆解：

- **一個強調色**：寶箱的金色。其餘是水的顏色加黑白。
- **字體數量最少**。中文字體檔很大，優先使用系統字體；若要用點陣或特殊字體，只用於英文與數字的少量標題。
- 常駐通訊按鈕的位置先保留，LINE 官方帳號開通後接上。

### 7.3 雙語

繁中與英文。首次進站依瀏覽器語言選擇，可切換，記住選擇。兩種語言的文字都在 HTML 裡，切換不需要重新載入場景。文案來源是 `original-site/text-zh.txt` 與 `text-en.txt`，依 `website-brief.md` 的決定修改。

## 8. 替代版本

**觸發條件**：瀏覽器沒有 `navigator.gpu`；取不到 adapter；裝置在最低畫質下仍遺失（上游目前在這些情況只顯示錯誤文字，見 `main.js` 開頭的 `fail()` 與 `device.lost`）；使用者設定減少動態效果；量測到幀率長時間低於門檻。

**內容**：同一份 HTML 內容層，改成一般的直向捲動頁面。每個地點是一個區塊，背景是該地點的場景截圖。截圖在有顯示卡的電腦上從完成的場景擷取，存放於 `site/fallback/`。電腦螢幕的位置以一般 `<video>` 元素疊上去播放預覽。

替代版本的內容必須與主版本完全相同：每個地點、每個視窗、表單都要能用。它不是錯誤頁。

替代版本可以在沒有顯示卡的環境開發與驗證，只有截圖要等場景完成。

## 11. 驗證

上游是靠「只看畫面、不看程式」的視覺評審反覆修正出來的（見 `abyssal-garden/prompt.txt`）。這裡沿用同樣的做法。

- **每次改動場景後**：用開發版（`npm run build:dev`）的 `F` 鍵飛完全程，用 `B` 鍵跑基準測試並記錄平均、第 99 百分位與最大幀時間。
- **每個地點**：擷取固定視點的截圖，檢查物件是否完整入鏡、螢幕是否清晰可讀、寶箱光暈是否明顯、有無閃爍、鋸齒、物件突然出現。
- **視覺評審**：若可使用子代理，讓它只看截圖與錄影，回報具體缺陷並排序，修到沒有「輕微」以上的問題為止。
